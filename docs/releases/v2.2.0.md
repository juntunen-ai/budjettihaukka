# Budjettihaukka 2.2.0 release record

Release date: 2026-08-27

## Scope

Version 2.2.0 promotes the React analytics interface to Firebase production
and packages the economic, debt and policy visualization work completed after
2.1.0. Natural-language questions still pass through the semantic resolver,
bounded analytics functions and the answer verification gate. The release
does not introduce free-form text-to-SQL.

## Production architecture

```text
Firebase Hosting
  -> React / TypeScript / ECharts frontend
  -> /v1/** and /health rewrites
Cloud Run: budjettihaukka-api
  -> semantic resolver and analytics engine
  -> read-only BigQuery semantic layer
  -> Firestore question library
Secret Manager
  -> admin API key
```

Runtime project: `valtion-budjetti-data`

Data project: `budjettihaukka-gpt`

Production URL: <https://valtion-budjetti-data.web.app>

## Cost and security controls

- Cloud Run scales from zero to at most two instances.
- BigQuery rejects queries estimated above 1 GB by default.
- Firestore browser rules deny all direct reads and writes.
- Admin question-library access requires a Secret Manager-backed key.
- LLM query planning is disabled in production by default.

Cloud Billing budgets are alerts rather than hard spending caps. The public
API still needs per-user rate limiting or App Check before large-scale public
campaign use.

## Data interpretation

Observed budget and macroeconomic series must be kept separate from policy
scenarios. Counterfactual and alternative-budget outputs are conditional model
calculations, not causal effects identified from observed data alone.

## Rollback

Cloud Run uses immutable Artifact Registry digests. Reapply the previous
known-good digest with Terraform, verify `/health`, and then roll Firebase
Hosting back to the preceding version if necessary. No rollback operation may
alter the production BigQuery semantic layer.
